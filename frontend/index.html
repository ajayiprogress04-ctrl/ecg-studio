How splitting works

Reads 100,000 rows at a time. Six-hour windows begin at the first valid timestamp. Invalid timestamps and non-numeric or missing signal values are discarded, matching the supplied Python script. The last partial window is retained. No signal filtering or resampling is applied.

Outputs retain timestamp, ecg_raw, ecg_mv, continuous_time, elapsed_time and block_number. Metadata comments are not copied, matching the original workflow. The plain column header may count as a discarded row.

Expected timestamp: 2026-06-18 08:52:24.000. Files must retain the comma-separated export structure expected by the original code.

Service connection & privacy

Checking the processing service…

Each recording has an isolated job. Input uploads are deleted after processing succeeds or fails. Outputs and abandoned uploads expire after the service’s retention period. “Delete job” removes available job files immediately. No recording values are written to application logs.

Capacity depends on the configured service and free disk space. Upload progress is measured in bytes; processing shows actual chunks and rows rather than an estimated percentage.
